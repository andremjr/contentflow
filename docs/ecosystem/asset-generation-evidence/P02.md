## Contrato adotado

O manifesto API v1 mantém todos os textos-base obrigatórios e pode declarar um mapa opcional `localizations`, indexado por locale BCP 47. O núcleo resolve cada texto por:

```text
locale exato → idioma-base → texto-base do manifesto
```

O mapa pode traduzir apenas a moldura visual fornecida pelo plugin:

- nome e descrição do plugin;
- label e descrição de `profileSetup`;
- nome e descrição de capabilities;
- label e descrição de portas;
- label de ações por item;
- título, descrição e labels de opções estáticas das propriedades de `blockConfigSchema`.

IDs, chaves de portas, valores de `enum`/`const`, aliases de perfil, configuração salva, bindings, nomes criados pelo usuário e conteúdo retornado pelo provedor não são traduzidos.

## Validação e compatibilidade

- Locale malformado é rejeitado antes da execução do plugin.
- Capability, porta, ação, propriedade ou opção traduzida que não exista no manifesto base é rejeitada.
- O schema continua com um único manifesto; não há duplicação integral por idioma.
- Manifestos antigos sem `localizations` preservam exatamente o texto-base e continuam válidos.
- Locales adicionais são permitidos; PT-BR, inglês e espanhol foram exercitados pela fixture neutra.

## Exemplos verificados

### Válido

```json
{
  "name": "Estúdio neutro",
  "localizations": {
    "en": { "name": "Neutral Studio" },
    "es": { "name": "Estudio neutro" }
  }
}
```

### Inválido

```json
{
  "localizations": {
    "english_US": {
      "capabilities": {
        "capability-inexistente": { "name": "Invalid" }
      }
    }
  }
}
```

O locale não é BCP 47 e o alvo não existe; a validação falha sem importar o handler.

### Fallback

Para `en-US`, uma descrição declarada em `en-US` prevalece; os demais campos ausentes usam `en`; campos também ausentes em `en` usam o texto-base. Para `es-MX`, o mapa `es` é usado. Para `fr-FR` sem mapa `fr`, todo o texto-base é preservado.
