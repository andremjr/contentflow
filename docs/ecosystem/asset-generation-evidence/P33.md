## Implementação

### Ações declaradas

`generate-image-in-browser` declara as quatro ações padronizadas:

| Ação         | Execução                                | Porta/efeito                                   |
| ------------ | --------------------------------------- | ---------------------------------------------- |
| `regenerate` | plugin, `invocation.mode = item_action` | devolve exatamente uma nova imagem em `images` |
| `replace`    | local no núcleo                         | substitui somente o arquivo do item            |
| `select`     | local no núcleo                         | seleciona somente o grupo do item/lote         |
| `download`   | local no navegador                      | usa somente URL materializada pelo núcleo      |

Os labels foram adicionados em português do Brasil, inglês e espanhol. O handler rejeita `item_action` diferente de `regenerate` e rejeita qualquer `outputPort` diferente de `images`.

### Refinamento e conversa

Cada variante incremental guarda uma correlação opaca com:

- a conversa `https://chatgpt.com/c/...` validada;
- o `connectionId` local já autorizado;
- o alias do perfil dedicado que produziu a variante.

Na regeneração, a conversa é reutilizada somente quando conexão e perfil continuam iguais. A mensagem de continuação contém o feedback de refinamento. Se a correlação estiver ausente, inválida, pertencer a outra conexão/perfil ou a conversa não puder mais ser aberta, o plugin inicia uma conversa nova e anexa somente a imagem reprovada, além das referências originais explicitamente autorizadas. A imagem anterior não é reenviada quando a conversa é reutilizada.

A geração inicial continua isolando cada `batch.itemId` em conversa nova; a correlação serve somente para refinar a própria variante depois da materialização e não compartilha contexto entre prompts.

### Mudança real, tentativa e isolamento

- A imagem anterior é resolvida por `services.resolveInputFile()` e recebe SHA-256 em memória.
- Uma resposta com os mesmos bytes é descartada e termina com `OUTPUT_VALIDATION_FAILED`, mensagem “sem mudança real”.
- Uma regeneração materializa no máximo uma imagem e usa `executionId`, `blockId`, nova tentativa, `batch.itemId` e hash dos bytes na identidade local do artifact.
- O núcleo preserva o ID universal, a posição e as tentativas do item; o plugin não inventa esses IDs.
- A ação não altera, reordena nem recaptura variantes vizinhas ou imagens já existentes no DOM.
