## Implementação

### Contrato do lote

`generate-image-in-browser` declara:

```json
{
  "maxConcurrency": 1,
  "itemOrchestration": {
    "inputPort": "prompt",
    "outputPort": "images",
    "mode": "sequential"
  }
}
```

O núcleo transforma a lista de prompts em chamadas atômicas, entrega um prompt escalar por chamada e acumula a coleção `images`. Como cada resposta atômica pode conter várias imagens, o acumulador achata as variantes em uma única lista ordenada. Os `itemUpdates` continuam usando chaves locais `image:0`, `image:1`, enquanto o núcleo acrescenta o `batch.itemId`; assim, variantes de prompts diferentes não colidem e mantêm proveniência.

### Isolamento e identidade

- Cada item de imagem com `request.batch` força `conversation.mode = "new"`, mesmo se o envelope original trouxer uma referência reutilizável.
- O ID de conversa do item não é devolvido como continuidade de um lote.
- `batch.itemId` participa das chaves idempotentes enviadas à Browser Bridge e da identidade do artifact materializado.
- O mesmo payload de imagem em dois prompts diferentes gera artifacts distintos, sem depender somente do hash dos bytes.
- O cancelamento já solicitado é devolvido como `CANCELLED` antes de abrir navegador ou iniciar o item seguinte.

### Persistência, retomada e fallback

A persistência permanece sob autoridade do núcleo. A suíte de fallback/orquestração comprovou que:

- o output de cada item é persistido antes do avanço;
- falha no perfil atual repete somente o item ativo no perfil seguinte;
- itens concluídos mantêm ID, output e estado após reload/retomada;
- a retomada começa no primeiro item pendente;
- cancelamento explícito não avança o fallback;
- outputs plurais são achatados sem repetir os anteriores.

## Fixture de três prompts

Fixture: `ecosystem/plugins/reference/chatgpt-browser-studio/fixtures/p32-sequential-image-prompts.json`.

| Ordem | `batch.itemId` | Prompt | Variantes associadas |
| --- | --- | --- | --- |
| 1 | `batch-image-city` | Uma cidade costeira ao amanhecer | `city-a`, `city-b` |
| 2 | `batch-image-forest` | Uma floresta bioluminescente à noite | `forest-a`, `forest-b` |
| 3 | `batch-image-desert` | Um observatório no deserto sob as estrelas | `desert-a`, `desert-b` |

Saída plural achatada esperada, mantendo a ordem: `city-a`, `city-b`, `forest-a`, `forest-b`, `desert-a`, `desert-b`.

O cenário de fallback falha no segundo item no perfil `primary-images`, repete somente esse item em `fallback-images` e prossegue para o terceiro. Após os dois primeiros itens estarem persistidos, reload/retomada aponta para `batch-image-desert`; `batch-image-city` e `batch-image-forest` não são reenviados.
