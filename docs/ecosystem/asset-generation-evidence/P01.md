## Problema caracterizado

O teste novo começou falhando com `O item incremental provider-generation mudou depois de concluído.`. A causa era a identidade incremental `key + outputPort`: duas variantes de um mesmo item, ou a mesma variante em outro item de lote, colidiam na mesma entrada persistida.

## Contrato adotado

```text
item de lote (ID universal do núcleo)
  + variantKey local do plugin (ou key legada)
  + outputPort
  └─> item de output (novo ID universal do núcleo)
```

- Em lote, o núcleo deriva o `batchItemId` da posição ativa e o persiste na correlação. O plugin não fornece nem inventa esse ID.
- `variantKey` é opcional. Sua ausência preserva a identidade de plugins v1: o núcleo usa `key` como chave da variante.
- `outputPort` é a porta que recebe a variante concreta. Em `item_action`, a regeneração devolve valor para essa mesma porta.
- Uma porta singular legada, por exemplo `image`, continua independente de uma nova porta plural, por exemplo `images`; o binding da primeira não é alterado.
- `select` é local ao mesmo `outputPort` e ao mesmo `batchItemId` quando houver lote. `download` não chama o plugin e só expõe URLs já materializadas pelo núcleo sob `/api/files/`. `replace` também não chama o plugin e aceita apenas texto compatível ou mídia local do mesmo tipo.

## Payloads de exemplo redigidos

```json
{
  "batch": { "itemId": "<core-batch-item>", "index": 1, "total": 2 },
  "itemUpdates": [
    {
      "key": "provider-generation",
      "variantKey": "candidate-b",
      "outputPort": "images",
      "state": "completed"
    }
  ]
}
```

```json
{
  "invocation": {
    "mode": "item_action",
    "action": "regenerate",
    "itemId": "<core-output-item>",
    "outputPort": "images"
  },
  "itemAction": {
    "key": "provider-generation",
    "variantKey": "candidate-b",
    "attempt": 2
  }
}
```

O primeiro ID identifica a entrada do lote; o segundo identifica a variante materializada. Ambos são atribuídos pelo núcleo, e a regeneração preserva o segundo ID e sua posição, acrescentando apenas uma tentativa ao histórico.

## Limitações e próximo pacote

O guia de desenvolvimento preexistente ainda orienta plugins a incluir `request.batch.itemId` em `key`; o protocolo normativo agora o torna desnecessário e autoritativo ao atribuir o ID no núcleo. P02 não depende desse guia, mas sua atualização deve ser planejada em um pacote documental próprio para evitar sobrepor a mudança preexistente.
