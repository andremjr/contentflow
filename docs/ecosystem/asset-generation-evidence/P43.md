# P43 — Geração de imagens no Vibes

Data: 2026-09-24

## Resultado implementado

O pacote independente `ecosystem/plugins/reference/vibes-browser-studio/` agora expõe somente a capability atômica `generate-images-in-browser`, mantendo a versão de desenvolvimento `0.1.0-dev.0` conforme a política do roadmap.

A capability:

- recebe `prompts` como texto, texto longo ou lista, com orquestração sequencial item a item pelo núcleo;
- aceita uma referência tipada de Personagem, uma de Cena e até seis de Estilo, limitadas a PNG/JPEG/WebP e 10 MiB;
- cria projeto novo em `auto/new` ou reutiliza somente `https://vibes.ai/projects/<id>` em `existing`;
- usa proporção fixa 9:16, quatro variantes e concorrência 1;
- persiste recibo no workspace antes do clique em **Gerar**;
- grava estado `unknown` antes do clique, impedindo reenvio cego após timeout;
- em `resume`, reabre o mesmo projeto e considera somente cards posteriores ao snapshot do recibo;
- exige um único `batchId`, ordinais únicos `1..4` e URLs HTTPS em `fbcdn.net`;
- publica snapshots parciais e `itemUpdates` com `batch.itemId` do núcleo + `variantKey` local `image:1..4`;
- entrega quatro artifacts remotos para materialização imediata pelo downloader seguro do núcleo;
- implementa `cancel` idempotente sem prometer cancelar o processamento já enviado ao provedor;
- implementa `item_action/regenerate` até `success` na mesma chamada e devolve uma única imagem substituta;
- declara `replace`, `select` e `download` como ações locais do núcleo;
- inclui `promptPreview`, README, fixture segura e localização PT-BR/EN/ES para toda a moldura visual.

Seletores, papéis, limites e regras do Vibes permanecem no plugin. A Browser Bridge não foi alterada no P43.

## Identidade e prevenção de cruzamento

```text
batch.itemId do ContentFlow
  └─ recibo lógico do plugin
      └─ batchId externo observado no mesmo projeto
          ├─ image:1 → mediaId content-1 → artifact estável
          ├─ image:2 → mediaId content-2 → artifact estável
          ├─ image:3 → mediaId content-3 → artifact estável
          └─ image:4 → mediaId content-4 → artifact estável
```

O teste de reconciliação fornece os cards fora de ordem, confirma a saída `1,2,3,4` e rejeita tanto dois lotes simultâneos quanto ordinal duplicado. Referências são resolvidas por porta técnica e preservam explicitamente os papéis `character`, `scene` e `style`; labels traduzidos não participam do binding.

## Matriz P03

| Estado observado      | Comportamento implementado                                                        |
| --------------------- | --------------------------------------------------------------------------------- |
| login/CAPTCHA         | permanece `pending` no perfil atual; não envia prompt na tela de intervenção      |
| rate limit            | `pending` com espera de 30 s                                                      |
| cota/upgrade/bloqueio | `pending` para intervenção no perfil atual                                        |
| recusa                | `CONTENT_REFUSED`, sem resultado fictício                                         |
| DOM incompatível      | `DOM_INCOMPATIBLE`, falha fechada                                                 |
| mídia ausente         | continua reconciliando até o timeout de 180 s                                     |
| timeout               | `TIMEOUT` repetível, preservando recibo e sem novo clique                         |
| cancelamento          | marca recibo, fecha recursos locais e informa que o efeito externo pode continuar |

Mídia aceita no máximo cinco redirects, 60 MiB e MIME `image/png`, `image/jpeg` ou `image/webp`. Cada redirect é validado antes da próxima requisição e o downloader do núcleo volta a aplicar HTTPS, hosts, DNS/SSRF, MIME, bytes e SHA-256 durante a importação.

## Cenários B8 cobertos automaticamente

| Cenário de imagem                                | Evidência automatizada                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------- |
| projeto novo/automático                          | normalização e caminho `auto/new`; driver cria pela home autenticada   |
| projeto por URL                                  | allowlist estrita de origem/rota e teste de rejeição de URL divergente |
| imagem sem referência                            | `start` com prompt simples                                             |
| Personagem                                       | resolução tipada e papel preservado                                    |
| Cena                                             | resolução tipada e papel preservado                                    |
| múltiplos Estilos                                | grupo ordenado e limite de seis                                        |
| duas referências de Personagem                   | `INVALID_INPUT` antes de automação                                     |
| quatro variantes                                 | reconciliação por lote/ordinal, schema `minItems=maxItems=4`           |
| seleção/regeneração                              | actions declaradas nas três línguas; regeneração síncrona de um item   |
| reload após envio                                | `resume` usa recibo/snapshot e não recompõe prompt nem referências     |
| cancelamento                                     | chamada `cancel` usa somente o `jobId` persistido                      |
| CDN                                              | HTTPS/host/credenciais/redirect/MIME/bytes validados                   |
| cota, limite, login, CAPTCHA e indisponibilidade | matriz de classificação testada                                        |

## Validação real pendente

O smoke real de geração não foi executado neste pacote. `P00.md` autoriza como perfis E2E apenas `flow-e2e`, `meta-e2e` e `chatgpt-e2e`; não existe perfil dedicado `vibes-e2e` aprovado/preparado. Usar uma sessão pessoal ou reaproveitar silenciosamente outro perfil violaria as regras de isolamento e autenticação da iniciativa.

Consequentemente, a implementação e as regressões automatizadas do P43 estão prontas, mas o critério observável “um prompt produz quatro imagens reais materializadas” permanece pendente até o mantenedor preparar explicitamente `vibes-e2e` pela ação **Preparar perfil do Vibes**. Nesse perfil ainda precisam ser exercitados no site real: sem referência, Personagem, Cena, múltiplos Estilos, reload entre envio/coleta, regeneração, cancelamento antes do envio e download do CDN. Nenhuma release, tag, publicação, alteração de versão ou site foi realizada.
