# P42 — Autorização do Vibes na Browser Bridge

Data: 2026-09-24

## Resultado

A Browser Bridge `0.4.0` autoriza o plugin `local.contentflow.vibes-browser-studio` somente em `https://vibes.ai/projects/<id>`. A origem `www`, a home, páginas de exploração, protocolos não HTTPS, segmentos extras e origens de outros provedores são recusados.

O pacote Vibes continua em `0.1.0-dev.0` e não declara geração de imagem ou vídeo. Este marco implementa e testa apenas o transporte necessário aos pacotes P43–P45; nenhum prompt foi submetido, nenhum projeto foi criado e nenhum custo externo foi provocado.

## Matriz de autorização

| Dimensão     | Aceito                                                                       | Recusado                                                                        |
| ------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| plugin       | `local.contentflow.vibes-browser-studio`                                     | ID ausente, desconhecido ou outro plugin usando a sessão Vibes                  |
| protocolo    | Browser Bridge v2                                                            | versão diferente ou handshake inválido                                          |
| perfil       | mesmo `profileId` do handshake                                               | perfil diferente                                                                |
| sessão       | token efêmero ativo                                                          | token ausente, expirado, substituído ou desconectado                            |
| execução     | `executionKey` válido e cancelamento escopado por plugin + perfil + execução | chave curta, execução cancelada ou cancelamento por sessão alheia               |
| comando      | SHA-256, janela máxima de 120 s, cache também escopado por plugin e perfil   | replay cruzado, ID inválido, comando futuro ou expirado                         |
| origem       | `https://vibes.ai`                                                           | `http`, `www.vibes.ai`, subdomínios e outras origens                            |
| rota         | `/projects/<segmento-opaco>` sem segmento extra                              | `/`, `/explore`, projeto ausente ou rota aninhada                               |
| aba          | aba exata ou mesma rota esperada dentro do perfil dedicado                   | aba de outro projeto ou origem                                                  |
| ações comuns | `ping`, `inspect`, `setText`, `click`                                        | qualquer ação não declarada na policy                                           |
| upload       | `setFiles`, 1–8 caminhos absolutos, alvo confirmado como `input[type=file]`  | caminho relativo, traversal, NUL, lista vazia/excessiva ou alvo diferente       |
| lease        | `leaseAcquire`, `leaseRenew`, `leaseRelease`, TTL de 20 s a 5 min            | renovação expirada, dono/aba/origem/rota divergente ou API `power` indisponível |

## Lease genérica

- heartbeat esperado a cada 20 s e TTL padrão de 60 s;
- teto de cinco minutos por aquisição/renovação;
- estado efêmero em `chrome.storage.session`;
- `chrome.power.requestKeepAwake("display")` e `autoDiscardable: false` somente durante lease ativa;
- liberação idempotente em conclusão explícita, cancelamento, desconexão, expiração, fechamento da aba, mudança de origem/rota, `pagehide` e substituição/expiração da sessão;
- alarme de limpeza a cada 30 s;
- cancelamento também remove o debugger da sessão;
- nenhuma regra, seletor ou nome de controle do Vibes entrou no mecanismo.

## Upload genérico

`setFiles` aceita somente uma lista limitada de caminhos absolutos já resolvidos pelo futuro handler a partir do staging autorizado. A ponte localiza o alvo pelos seletores fornecidos pelo plugin, confirma por CDP que o nó é um `INPUT` do tipo `file` e então usa apenas `DOM.setFileInputFiles`. Não há superfície para método CDP arbitrário, object ID escolhido pelo plugin ou caminho com traversal.

Os limites de MIME, bytes, quantidade por papel e resolução pertencem às capabilities P43–P45; não foram antecipados na ponte.

## Identidade, replay e fila

- `executionKey` do cliente inclui execução, bloco, capability, tentativa, item e perfil;
- `commandId` inclui execução, ação e chave estável da operação;
- respostas em cache exigem o mesmo plugin, perfil e execução;
- operações em voo exigem também a mesma sessão;
- comandos continuam serializados por aba;
- replay devolve a resposta anterior sem repetir clique, upload, aquisição de lease ou outro efeito.

## Regressão dos plugins existentes

As policies, origens e ações de Flow, ChatGPT, Claude, Gemini, Grok, Meta e MAI permaneceram inalteradas. A suíte de plugins de navegador passou integralmente, incluindo os testes específicos de Flow, ChatGPT e Meta.

Os testes da extensão cobrem autorização, origem/rota, perfil, sessão, replay, expiração, fila, cancelamento, detach, upload, lease, mudança de rota e limpeza. Os testes do cliente cobrem URL estrita, identidades idempotentes, handshake, comandos mínimos e descarte da sessão.

O `npm run lint` global foi executado e permaneceu vermelho por um baseline anterior ao P42: 147 erros de formatação concentrados em `ecosystem/plugins/reference/google-flow-browser-images/handler.mjs` e `ecosystem/plugins/reference/google-flow-browser-images/scripts/p14-live.mjs`, além de um warning existente em `src/components/output-character-count.tsx`. Os arquivos JavaScript tocados pelo P42 passaram isoladamente; as expectativas não foram relaxadas e os arquivos fora do escopo não foram corrigidos.

## Limite deste marco

Não houve E2E de geração real porque P42 não declara nem implementa uma capability de geração. A validação de conta, submissão, recibo, coleta e materialização pertence a P43–P46 e não deve ser simulada como sucesso neste pacote.

## Critério de saída

P42 está concluído: Vibes possui policy própria e mínima, a Browser Bridge só opera na sessão/perfil/execução/aba/origem/rota corretos, ações novas foram limitadas às necessidades genéricas comprovadas no P40, recursos são liberados em todos os caminhos testados e os plugins existentes permaneceram funcionais.
